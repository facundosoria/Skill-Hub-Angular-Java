El problema

Somos once equipos trabajando en paralelo sobre el mismo sistema. Sin una fuente única, cada equipo inventa su forma de manejar errores, de nombrar endpoints, de armar un formulario. A los seis meses hay once dialectos y nadie puede moverse entre equipos sin reaprender todo.

Los documentos de Confluence no lo resuelven, porque nadie los abre en el momento exacto en que está escribiendo el código.

La idea

Un solo catálogo de convenciones, con dos caras sobre los mismos datos:

  • Para personas: esta web. Buscás, leés, proponés cambios. Todo queda versionado y auditado.
  • Para agentes: un endpoint MCP. Tu IDE se conecta con tu key y el agente consulta el catálogo solo, antes de escribir código.

Las dos leen la misma base. Lo que se aprueba acá es lo que el agente lee un segundo después: no hay git pull ni versiones desfasadas entre equipos.

Por qué no es un marketplace

La palabra aparece seguido y conviene sacarla del medio, porque el modelo mental equivocado lleva a decisiones equivocadas.

En un marketplace hay muchos oferentes compitiendo y quien consume elige entre opciones. Acá pasa exactamente lo contrario: si aparecen seis versiones distintas del skill de botones, eso no es variedad — es el fracaso del proyecto.

Qué es un skill

Un archivo Markdown con un frontmatter determinista y un cuerpo estructurado con la regla ## Rule y ejemplos concretos.

Qué es MCP

Model Context Protocol: estándar abierto para conectar asistentes de IA de manera estandarizada y segura con servidores de herramientas y contexto.

Implementación técnica

Backend en Spring Boot 3.4 (Java 21) con PostgreSQL y búsqueda vectorial/full-text. Frontend en Angular 22 standalone, signals y Tailwind CSS.

Tu API key

Tu identidad como desarrollador: autentica las consultas de tus agentes de IA e imputa auditoría al equipo correcto.

Conectar tu IDE

Configuración directa en Cursor, Claude Code o Windsurf agregando el endpoint /api/mcp con tu Bearer token.

Cómo lo usa la IA

El agente busca proactivamente en el catálogo antes de editar o crear código. No requiere que le indiques el skill por nombre.

Las tools MCP

Lectura (search_skills, get_skill, sync_skills, list_skills, get_port_registry) y escritura auditada (propose_skill, propose_revision).

Reglas y auditoría

Todas las propuestas viajan como provisionales hasta que un administrador las audita en la vista de revisión, asegurando que solo el código consensuado sea canónico.
